# Android R8 release build

After `pixiewood generate`, run:

```sh
python3 build-aux/configure-android-r8.py .pixiewood/android/app
```

This enables code shrinking, optimization, obfuscation and resource shrinking
only for the generated release build. It copies `android/proguard-rules.pro`
into the generated Gradle project and preserves theme resources that GTK may
access from native code. Run `pixiewood build` afterwards.

GTK loads its Java bridge classes and members by name through JNI. The rules
preserve that bridge surface while allowing Java helpers to be optimized.
R8 does not obfuscate the Vala/C/C++ native libraries or gettext assets.

The release workflow requires a real R8 mapping file and verifies 14 native
bridge class names before signing or publishing. Mapping and shrinker diagnostics
are saved separately as the `android-r8-mapping` Actions artifact for retracing
crashes. They are not included in public Release attachments.

Before relying on a new GTK revision, review native RegisterNatives/FindClass/
GetMethodID/GetFieldID usage against these rules. On a device, verify startup,
Chinese UI, file picking, video conversion, save, extraction, repair, keyboard
input, clipboard and returning from the background. A successful build and
mapping check do not replace device testing.
